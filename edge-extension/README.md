# HKUST 空调循环控制（Edge 扩展）

此扩展只在 `https://w5.ab.ust.hk/njggt/app/home` 的学校空调主页发送空调控制请求。它在页面的空调状态卡片中加入开机和关机分钟数、开始循环、应用修改、停止循环按钮。每段可设 1–1440 分钟。当前版本为 1.1.19。

## 1.1.19：短暂接口异常恢复与开关超时优化

自动切换前 GET 查询返回 HTTP 502／503／504 时，现在沿用有限查询恢复：失败后等待 30 秒，最多增加一轮完整核验，截止固定为原定切换时间后 60 秒。必须重新确认学校定时器与实际状态，且尚未发送指令；其他来源或错误不新增恢复。恢复期间禁止修改时长，停止按钮始终可取消。

GET 仍每次等待 8 秒，超时立即重试一次；POST 等待上限调整为 15 秒，包括响应正文，仍不重试。30 秒操作总期限与取消优先，已在恢复期限内发送的指令可以继续等待并确认，但不延长操作总期限。HTTP 200 或事后页面状态不代替业务结果与实际状态确认，未知结果仍停止。

报告保存首次恢复原因（错误码、HTTP 状态、接口与序号），成功、取消和停止保留真实关联；唯一匹配的浏览器请求补充 HTTP 状态、响应头到达／完成时间及相对取消的时间差。补充证据不改写原始请求超时或指令未确认结论，旧字段缺失保持未知，不增加采集权限、响应正文或日志容量。

此版本降低慢响应和短暂服务异常导致的停止，不能保证学校服务永不出错。更新后需重新加载扩展、刷新学校主页并手动开始。

打包脚本为仓库根目录的 `scripts/package.ps1`，仅打包明确列出的运行文件和公开文档，生成 SHA-256 校验文件。测试、个人报告、备份、学校网页快照和运行状态不进入下载包。循环控制逻辑、默认时长、接口、权限和依赖均未改变；沿用 1.1.17 的取消报告修复。尚未上架扩展商店，更新仍需手动下载、替换原目录文件并重新加载。

## 1.1.17：取消不再误生成故障报告

普通停止或关闭页面时，如果当时只是在读取/核验状态、尚未发出开关指令，不再生成 `E_CANCELLED` 故障报告。此前该路径会先写一份取消报告，关闭页面时还会再写一份 `E_PAGE_CLOSED`，导致报告目录出现没有独立故障含义的文件。

如果开关 POST 已经发出但尚未确认，停止时仍保留一份 `E_CANCELLED` 报告并标记 `outcomeUnknown: true`，避免丢失“结果未知”的证据。查询超时恢复被取消时，仍保留一份 `source: queryRecovery`、`outcome: cancelled` 的关联结果；关闭页面仍按原规则生成 `E_PAGE_CLOSED`。

本地验证：447 项模拟测试全部通过，扩展、测试与预览共 34 个 JavaScript／MJS 文件语法检查通过。新增覆盖停止/关页发生在预检读取期间、停止“应用修改”、以及开关已发出但未确认的停止；权限、控制规则、超时、报告格式和依赖均未改变。日志见 `../test-results-1.1.17.txt`；原版备份在 `../.backups/1.1.16-before-cancel-report-fix/`。全部测试使用模拟接口，没有操作真实空调。

升级：在 `edge://extensions` 重新加载此目录并确认 1.1.17，再刷新学校主页；重新加载和刷新会结束原循环，不额外关机，使用时需手动开始。

## 1.1.16：查询超时恢复与诊断修复

正常自动切换的预先查询连续超时、且尚未发送任何开关指令时，最多恢复到原定切换时间后 60 秒。两次读取超时后等待 30 秒，再完整查询学校定时器和实际状态；下一次查询已无法安排在期限内则直接停止。查询受剩余期限限制，发送 POST 前（包括读取令牌之后）再次检查期限；已经发出的指令仍按原有总操作期限确认结果，绝不重发。浏览器闹钟可能延迟，迟到不会获得新的恢复时间。

恢复期间保存原循环编号、阶段起点、分钟数、计时版本和两小时保活节奏。界面显示原因和剩余秒数，禁止修改时长，停止仍可取消。后台重新唤醒从同一恢复任务继续；刷新或认证跳转不延长期限。扩展更新、重载及浏览器会话丢失仍结束旧循环，不从历史记录自动启动。启动、立即应用时长、手动检查、保活查询和已发送开关后的确认查询不新增此恢复机制。

恢复记录 `queryRecovery` 包含关联编号、原切换时间、固定期限、计划重查时间及最多四轮经过白名单过滤的查询证据。首次超时保留原始报告，最终恢复、取消或停止另存关联结果；中间过程不重复生成独立故障。`source: queryRecovery`、`outcome`、`recovered`、`switchCommand` 和 `outcomeUnknown` 区分等待、成功、取消、停止及开关结果未知；`E_QUERY_RECOVERY_TIMEOUT` 表示已到恢复期限。

修复成功请求结束／业务响应在后台休眠后丢失的问题，以及相同错误码误关联其他操作的问题。请求补充 `cancelledAt`、`cancelledBy`、`cancellationOrigin`（请求自身超时或上层取消），`ERR_ABORTED` 本身不代表网络主动断开。报告补充截断及缺失结束记录标记；迟到证据只补充原故障，保留其关键操作记录，并继续限制每份诊断最多 64 个事件、32 条网络记录。学校页面自身请求是旁证，不能授权切换；缺失记录、无法获得 DNS/TCP/TLS 耗时、服务器内部原因仍标为未知。

字段贯通缓存、文件导出及页面通信失败记录；不记录令牌、Cookie、响应正文，不增加网络探测、依赖或权限。诊断写入失败不改变控制结果，关键循环／闹钟写入失败仍停止。原始问题仅确定为等待响应超时，以上修改不能证明或修复学校服务器或网络链路的内部故障。

升级：在 `edge://extensions` 重新加载此目录，再刷新学校主页，确认实际状态后手动开始循环。更新会结束旧会话；本地模拟验证不代替真实浏览器长期运行验证。

本地验证：443 项测试全部通过，34 个 JavaScript／MJS 文件语法检查通过，权限、主机范围和依赖与 1.1.15 相同。模拟接口重现两次超时后在原计划后第 46 秒恢复，只发送一次切换指令；覆盖停止、刷新、认证、后台重建、过期排队、未确认指令及存储故障。Edge 本地预览通过 260 像素面板及 200% 放大验收，输入／应用禁用而停止可用，未发生横向溢出。日志见 `../test-results-1.1.16.txt`；截图见 `../ui-preview/qa/query-recovery-1.1.16.png` 和 `../ui-preview/qa/query-recovery-200pct-1.1.16.png`。原版备份在 `../.backups/1.1.15-before-query-recovery/`。全部测试使用模拟接口，没有操作真实空调。

## 1.1.15：运行中修改时长

运行中直接修改两个分钟数，再点击“应用修改”，无需停止循环。输入时显示“尚未应用”及预计剩余时间；应用期间显示加载并禁止重复提交，停止按钮仍可取消。新时长影响当前阶段和以后每轮，已经过去的时间不会重置：例如开机 10 分钟、已运行 7 分钟，改成 12 分钟还剩 5 分钟；改成 5 分钟会立即核验并关机。关机阶段同理。只有剩余时间可以归零或变负，总时长仍为 1–1440 分钟正整数。

立即切换仍须确认登录、学校定时器和实际状态；一次修改最多切换一个阶段，下一段从确认成功后计时。修改未来时长不额外请求学校接口。修改只在点击后生效，成功后保存为下次启动默认值，保留原循环编号和两小时保活节奏。页面推送和倒计时不会覆盖尚未提交的输入。

后台将修改与正常切换串行执行，以 `runId`、`timingRevision` 和浏览器提供的页面身份核对请求。如果自动切换先完成，返回 `E_TIMING_STALE`、更新显示并保留输入，需核对后再次应用。旧闹钟核对 `scheduledTime`，不能操作新计划。修改总期限 30 秒（包含排队及初始化核对），页面等待最多 35 秒；排队过期不会在稍后开始执行。原计划已迟到超过一分钟时仍停止，不能靠延长时间恢复。认证／刷新恢复期间、结果未知或控制锁定时不允许修改。

循环新增 `phaseStartedAt`、`timingRevision`、`lastTimingChange`。旧的有效会话缺少字段时从原截止时间和阶段时长推算起点，版本默认为零；不会从已结束的扩展会话自动启动。关键记录或闹钟写入失败仍停止，未确认的 POST 永不重发。

消息 `aircon:updateDurations` 携带 `runId`、`timingRevision`、`onMinutes`、`offMinutes`，成功及执行失败均尽可能返回当前 `view`。报告新增 `updateDurations` 来源和 `timingChange`：修改前后时长、阶段起点、原／计算／实际安排时间、版本、立即切换标记和结果。最近一次修改随循环持久保存，后续故障仍可定位；页面通信失败会保留提交值及“结果未知”。所有字段经白名单过滤，缓存、重启和导出保持兼容，旧报告新增字段为 null，格式版本仍为 1。

更新时在 `edge://extensions` 重新加载并确认 1.1.15，再刷新学校主页、手动开始循环。没有新增权限或依赖。扩展更新会结束旧会话，不自动操作空调。

1.1.15 本地验证：402 项模拟测试全部通过，扩展与预览共 33 个脚本语法检查通过。覆盖双阶段加减时间、零／负剩余时间、下一轮参数、旧闹钟与并发提交、排队过期、停止／刷新／认证恢复、未确认 POST、写入失败、旧会话与旧报告兼容。Edge 本地预览确认加载期间禁用输入及重复提交、保留停止，以及 260 像素面板和 200% 放大布局；截图见 `../ui-preview/qa/duration-panel-1.1.15.png` 和 `../ui-preview/qa/durations-200pct-1.1.15.png`。测试日志见 `../test-results-1.1.15.txt`。没有请求真实学校接口或操作空调，长时间实际运行仍待更新后验证。

## 安装

1. 在 Edge 地址栏打开 `edge://extensions`，开启“开发人员模式”。
2. 点击“加载解压缩的扩展”，选择仓库中的 `edge-extension` 文件夹（下载版选择 `HKUST-AC-Cycle`）。
3. 登录学校空调网页并刷新主页。看到“自动循环”卡片后设置时长并点击“开始循环”。

不需要安装 Node、Tampermonkey 或任何运行依赖。Node 只用于可选的本地测试：在本目录运行 `npm test`。

已有旧版扩展时：在 `edge://extensions` 对 HKUST AC Cycle 点击“重新加载”，再刷新学校主页。仅修改文件不会更新已经注入页面的脚本。重新加载及刷新会结束原有循环，不额外关机；新版需手动开始。

## 使用与限制

### 1.1.14：认证跳转恢复与按标签页取证

本版针对 10 月 21 日 15:29 的 `E_PAGE_CLOSED`：现场确认浏览器报告离开主页，附近诊断显示登录页；用户无需刷新或手动登录即可重新开始。学校代码包含自动 CAS 认证往返，因此短暂认证跳转是当前候选原因，旧报告缺少业务码和完整返回过程，尚不能确认为唯一根因。

运行中的同一标签页进入学校 `/login` 或 `/callback/cas` 时，先暂停，保留原阶段、原切换时间和两小时保活节奏。已进入认证恢复的标签页可以继续经过 `https://cas.ust.hk/cas/login`；直接离开主页去 CAS、退出登录、关闭或进入其他页面仍会结束循环。CAS 地址依据[学校公布的 CAS URLs](https://itso.hkust.edu.hk/services/cyber-security/cas/required-cas-urls)。插件不代填账号、不修改令牌，也不主动发起登录或页面跳转。

恢复窗口沿用 60 秒，且不得晚于原切换时间后 60 秒；连续跳转和后台再次唤醒不能延长期限。返回主页后重新读取当前页面的令牌，核验学校定时器和实际空调状态，再接续原计划。到期会取消正在进行的恢复查询。认证仍失败、状态不符、原生定时器冲突或存在未确认的开关指令时停止，POST 不重试，也不额外开关空调。手动停止后，迟到的返回事件不能重新启动循环。

新增只读 `webNavigation` 权限及 CAS 主机访问范围，用于识别浏览器报告的认证路径。学校应用页新增两段 `document_start` 诊断脚本：页面侧观察原有 XHR/fetch 的白名单接口，隔离侧过滤并转发元数据。只提取 HTTP 状态、数字 `meta.code`、接口路径、方法和时间，不保存响应正文、请求头、令牌、账号、CAS ticket 或 URL 查询参数。fetch 返回原 Promise，诊断只读取有大小和时间上限的响应副本；不会为了取证增加学校查询。该实现使用浏览器的 [MAIN / ISOLATED content script](https://developer.chrome.com/docs/extensions/reference/manifest/content-scripts) 支持。

报告新增：

- `diagnostics.targetTabId`、页面和请求的 `tabId/documentId`：关联当前循环，避免其他学校标签页覆盖现场。
- `diagnostics.lifecycleEvents`：独立保留最近 64 条页面生命周期和恢复事件，包括路由类别、浏览器导航阶段、跳转类型和白名单网络错误；不会被普通请求阶段日志挤掉。
- `diagnostics.pageResponses`：当前标签页最近 32 条页面请求摘要，含数字业务码。仅在唯一匹配时关联浏览器请求编号；不确定时标注 `ambiguous/unmatched`。页面侧证据不作为控制授权，也不能单独证明服务端内部原因。
- `cycle.recovery`：恢复起点、固定期限和类型。认证恢复成功也自动保存 `source: authRecovery, recovered: true` 报告；真实失败保留原始错误。
- 诊断序号及最近报告关联会持久保存。报告生成后 60 秒内、后台重启后到达的同标签页返回证据可补入同一文件，不改写原始控制结果。缺少的采集覆盖、旧版未关联事件仍明确标为未知。

页面离开后不再因状态通知重复查询；已在途的只读 `getState` 仍被拒绝，但不再产生第二份伴随故障报告。真实控制请求继续严格校验来源。

更新：在 `edge://extensions` 重新加载，确认 **1.1.14** 及新增权限已生效，再刷新学校主页并手动开始。旧循环不会跨扩展重载自动恢复；报告目录原授权继续使用。旧版源码备份位于 `../.backups/1.1.13-before-auth-recovery/edge-extension`。

本地验证：354 项测试全部通过，扩展及预览共 32 个脚本语法检查通过，差异空白检查通过。覆盖认证经 CAS 跨文档返回、同文档返回、后台重启、固定恢复期限及查询取消、真实认证失败、状态和定时器冲突、未知开关指令、停止后不恢复、重复报错、多标签页隔离、诊断序号延续和同文件补写、XHR/fetch 不改变请求结果、隐私过滤和旧版报告兼容。测试输出见 `../test-results-1.1.14.txt`。

验证使用模拟学校接口，没有操作实际空调。需要在真实 Edge 中更新后确认诊断脚本覆盖和长时间运行；学校服务端内部故障、需要人工输入的认证或未列入支持范围的外部认证路径不能保证自动恢复。下一次反馈请保留故障报告和附近的 `authRecovery` 报告，无需提供账号令牌。

### 以往版本

## 两小时保活

循环启动后，扩展使用独立的浏览器闹钟每 120 分钟读取一次页面当前登录令牌，并查询空调状态。保活不会刷新或重置页面，不发送开关指令，也不改变循环阶段或下次切换时间。未运行循环时不保活；停止、关闭／离开页面或循环出错结束时，同时取消保活。刷新恢复期间跳过保活读取，接续后保留原节奏。

保活 GET 超时会立即重试一次；最终失败会在面板显示发生时间、错误代码和原因，原循环仍运行，不再额外重试。下次成功只清除保活自身的警告，不覆盖原循环的错误；定时开关出错时仍按原规则停止。后台再次唤醒时，会为仍有效的循环恢复缺失的保活闹钟，沿用启动时的两小时节奏，不补发错过的请求；不会因此恢复丢失的切换闹钟。

这是对长时间运行失效的一次保活尝试，尚未确认原故障原因，不能保证修复标签页冻结、登录令牌过期或学校服务异常。浏览器可能延迟闹钟，保活不能保证唤醒冻结页面或休眠电脑，也不会修改 Edge 的休眠设置。实际效果需要在 Edge 中持续运行至少 4 小时、跨过两次保活验证；本地测试只使用模拟接口。

## 自动错误报告

首次使用 1.1.7 时，在 `edge://extensions` 重新加载扩展，再刷新学校主页。重新加载和刷新会结束旧循环，不额外关机，使用时需手动重新开始。

1. 展开插件面板右上角“说明”，点击“报告设置”（也可在扩展详情中打开扩展选项）。
2. 点击“选择报告目录”，选中自己的本地报告目录（例如“文档”中的 `HKUST-AC-reports`）并允许写入。
3. 看到“自动保存已就绪”后即可关闭设置页。以后运行、接口、通信或保活出错时，后台会自动保存 `aircon-error-时间-编号.json`。

每份报告包含格式版本、错误发生时间、插件和浏览器版本、操作来源、循环设置与阶段、下一次切换时间、最近确认的空调状态和确认时间，以及本次操作最多 10 条请求摘要（方法、固定接口路径、HTTP／学校错误码和耗时）。清理循环前会先抓取快照，不为生成报告额外访问学校接口。

报告中的 `expectedOn` 是预期状态，`lastConfirmedStatus` 才是最近一次读取的状态，不能代表出错时的实时物理状态。`switchCommand.sent` 只表示客户端已发起开关请求，不证明服务器收到；`confirmed` 只有随后查询到目标状态时才为 true。后台通信失败的报告标明 `page-cache` 和 `outcomeUnknown`，其中的循环信息可能已经过时。

1.1.6 将找不到接收端、回复前通道关闭和空回复分别显示为不同错误代码。通信报告增加 `communication.messageType`（例如 `aircon:initialize`、`aircon:start`）和白名单原因 `communication.reason`：`NO_RECEIVER`、`PORT_CLOSED`、`CHANNEL_CLOSED`、`CONTEXT_INVALIDATED`、`NULL_REPLY`、`UNDEFINED_REPLY`、`TIMEOUT` 或 `UNKNOWN`。未知异常不猜测原因；扩展上下文失效仍使用通用通信错误代码，并在报告中标明 `CONTEXT_INVALIDATED`。旧报告仍能保存，缺少的诊断信息不会推测补全。

此更新修复通信诊断信息丢失，不代表已经修复启动通信故障的根因；没有增加握手、自动重试或额外请求。控制操作发生这些通信错误时仍按“结果未确认”处理，禁止直接重复启动，保留停止按钮。

1.1.7 修复两处已复现的代码缺口：后台使用浏览器提供的当前标签页地址判断是否在主页，兼容从登录页或回调页不刷新整页跳转回主页；同时校验消息属于本扩展、学校应用域名和主框架。来源信息缺失或不合规时返回 `E_MESSAGE_SOURCE`，明确表示本次指令未执行，不操作循环，也不自动再请求状态。网页自报地址不参与授权判断。

页面会在更新视图前校验回复的 `ok`、成功回复中的 `view` 及其必要显示字段。格式错误返回 `E_BACKGROUND_INVALID_REPLY`，结束等待并保留最后有效视图；控制结果仍按未知处理，不重发指令。后台已提供报告编号时沿用该编号，不另建页面报告。此修复不证明已确定 1.1.6 那次真实空回复的全部根因。

通信报告新增 `sourcePage`（`HOME`、`SCHOOL_APP`、`OTHER`、`MISSING` 或未知时为 null）和 `tabIsHome`（true／false／未知时为 null）。后台的来源判断记录在 `communication` 中；页面缓存只能记录采样时是否仍在主页，无法得知后台收到的来源分类。新增白名单原因包括 `INVALID_REPLY`、`ACCEPTED`、`EXTENSION_MISMATCH`、`TAB_ID_MISSING`、`FRAME_REJECTED`、`SOURCE_REJECTED`、`TAB_URL_MISSING` 和 `TAB_NOT_HOME`，不记录完整来源 URL、查询参数或登录票据。`ACCEPTED` 仅表示来源校验通过，不表示空调操作成功。旧报告缺少这些字段时保持未知，版本号仍保留生成时的版本。

报告只记录白名单字段和固定错误说明，不保存令牌、Cookie、登录记录、账号资料、原始请求头或响应正文。原始异常堆栈只提取本扩展的文件名和行号。

目录未授权、权限失效或文件写入失败时，报告会留在插件本地缓存；重新选择目录或点击“重试保存”后补写，后台重新唤醒也会尝试补写。缓存保留最新 20 个报告编号，诊断字段按 128 KiB 紧凑 JSON 预算限制（文件缩进另计）；超出 20 份会移除最旧缓存，已保存文件不自动删除。刷新页面和关闭浏览器不会主动清除缓存，卸载扩展或清除其数据会删除缓存。

报告文件写入使用独立队列；关键运行记录、中断原因及其报告先写入插件本地缓存，再清理会话。正常主动停止及成功刷新接续不生成故障报告；关闭／离开页面和恢复失败会生成报告。目录或文件保存失败保留缓存，不覆盖原始控制错误；关键缓存写入失败则禁止后续空调指令。报告保存本身不访问学校接口。

本地模拟测试覆盖报告内容、隐私过滤、权限失效、缓存补写和文件流关闭确认。真实 Edge 的目录授权必须由用户完成；授权后仍需验证设置页关闭时的后台自动落盘。

1.1.7 的 Edge 验收：重新加载扩展后，分别检查直接打开／刷新学校主页，以及从登录页跳转回主页时能否完成初始化；无需点击开始循环即可验证。若仍出错，查看新版报告中的消息类型、来源分类和拒绝原因。本地模拟通过不代替这项真实浏览器验收。

## 自动诊断字段（1.1.13）

| 字段 | 能确认的内容 |
| --- | --- |
| `faultBoundary` | 客户端失败阶段、请求编号、相关浏览器阶段／网络错误、取消原因；服务端内部原因始终标为未知 |
| `requests[].timings` / `response` | 取令牌、等响应头、读正文、JSON 解析和校验耗时；响应类型、大小及是否转向登录页，不含正文 |
| `operation.queueWaitMs` | 操作排队耗时，与实际执行耗时分开；旧报告缺失时为 null |
| `diagnostics.network` | 插件与学校页面请求的浏览器编号、事件顺序及错误；关联不唯一时明确标为 ambiguous／unmatched |
| `diagnostics.site` / `events` | 页面可见性、online 标志、刷新／隐藏／冻结事件、脚本错误位置、登录年龄和页面脚本名；内容脚本与标签页观测分别有时间戳 |
| `diagnostics.worker` / `unfinishedOperations` | 后台实例更换，以及旧记录是否缺少操作结束标记，不自动推断退出原因 |
| `diagnostics.coverage` | 网络观察、资源计时、历史读取及持久化是否可用；不足之处会明确标记 |

每份报告包含最近最多 64 条事件和 32 条网络摘要。资源计时在浏览器允许时补充 DNS、连接、TLS、等待和下载耗时；跨来源受限或连接复用无法区分时保留未知，不能把零值解释为“DNS／TLS 没问题”。`sendHeaders` 仅表示浏览器准备发送，不证明学校服务器收到；插件超时后出现 `ERR_ABORTED` 通常是客户端取消的结果，不能单独当作网络根因。墙钟／单调计时差和超时偏移用于观察计时异常，也不能单独证明电脑休眠。

白名单过滤在写本地缓存和导出时执行。不会保存令牌、Cookie、账号、完整 URL／查询参数、任意异常文字、原始请求头或响应正文。旧报告的诊断字段保持未知，版本号不更新。无法在插件里看到学校数据库、设备网关或代理内部阶段，因此报告能收窄到可观察边界，不能保证仅凭客户端日志确定服务端内部根因。

## 接口依据

项目内保存的学校页面脚本明确指定生产接口为 `https://w5.ab.ust.hk/njggt/api`。`GET /app/prepaid/ac-status` 返回 `data.ac_status.DisconnectRelay`；`GET /app/prepaid/ac-timer` 返回 `data.ac_timer`；`POST /app/prepaid/toggle-status` 使用 `{ "toggle": { "status": 1 或 0 } }`。学校站点若更新接口，扩展会停止并报错，不会猜测新的请求格式。

历史修复必须保留：不要使用脚本里的 SIT 测试服务器；缺少 `ac_timer` 与学校网页一致，按未设置定时处理。学校原生开关的显示可能滞后，循环以 API 状态为依据，不直接篡改学校页面的 ON/OFF 显示。

## 启动速度与超时诊断

启动时并行读取学校定时器和空调状态，两者通过后才开机。已经 ON 时不重复发送 ON；原先 OFF 时发送 ON，最多进行 3 轮状态确认，后两轮各等待 1.5 秒。每轮 GET 遇超时可重试一次，仍受 30 秒操作总期限约束。确认后的时间作为开机阶段起点。保存默认时长和通知界面不阻塞启动结果。没有真实学校网络测速，因此不承诺固定启动秒数。

点击按钮会立即显示操作反馈。若恰好在页面初始化期间点击开始，后台初始化结束后才启动；停止不等待页面初始化回复。旧初始化或状态读取的回复不能覆盖更新的操作结果。通信恢复后会清除临时读取错误，但保留需要处理的启动失败信息。

开始／停止使用操作回复更新界面，避免重复读取状态；循环状态和提示通过一次本地存储调用读取。倒计时复用页面元素，内容未变时不重复改写；空闲时不扫描页面。默认分钟数立即可用，迟到的默认值不会覆盖已编辑的输入。初始化失败后，再次点击开始可以在同一次点击的 35 秒期限内重试初始化。

后台重新唤醒时，在控制／状态事件前核对运行检查点及浏览器闹钟，仅使用本地 API，不增加学校请求。正常运行的闹钟丢失或时间不一致时停止并报告；由该闹钟唤醒时允许处理已触发的闹钟。已记录的页面恢复期间允许切换闹钟已被消费，核验通过后仅按原计划重新安排，不从持久记录重建已结束的循环。

- 检查标签页、读取页面登录状态：各最多 3 秒。
- 单次扩展会话存储或浏览器闹钟调用：最多 2 秒，正常返回时不等待截止时间。读取可随停止操作取消；已提交的浏览器写入无法撤回，写入超时后禁止该后台继续发出空调指令，需重新加载扩展。
- 每次学校请求：GET 最多 8 秒、POST 最多 15 秒，包含等待响应正文；操作总期限或取消先到时优先终止。GET 超时最多立即重试一次，POST 不重试。
- 单次启动／切换／状态检查：30 秒时发出取消信号，阻止后续控制步骤，重试不延长总期限。
- 页面等待后台操作：最多 35 秒；纯状态读取为 5 秒。超时显示“结果未确认”，禁止直接再次启动，可点击停止或刷新页面。页面还在运行时显示已等待秒数。

这些超时依赖浏览器执行 JavaScript，电脑休眠或页面冻结时无法保证界面按秒更新。取消请求也不能撤回学校服务器已经收到的指令；即使收到超时，空调状态仍需用户确认。
